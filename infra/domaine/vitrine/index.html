Un sas pour les paquets logiciels. Chaque nouvelle version attend trois jours derrière une passerelle sans Internet, est analysée chez vous (code, comportement, IA locale), puis signée. Vos serveurs ne voient jamais la dernière version publiée sur Internet : seulement la dernière version vérifiée.

déc. 2024ultralytics PyPI
La 8.3.41 installe un mineur. La 8.3.42, publiée pour corriger, contient le même code. L'urgence est le meilleur déguisement.
sept. 2025Shai-Hulud npm
Un ver, plus de 500 paquets, vol des jetons GitHub et des clés cloud. La CISA demande de revenir aux versions d'avant le 16 septembre : un délai, imposé après coup.
mai 2026TanStack, Mistral AI npm, PyPI

3 Le sas trois zones, un seul passage vers Internet

Le parcours d'une nouvelle version

  1. 01Attente3 jours. La veille lit OSV et les flux de chercheurs.
  2. 02Analyse statiqueTyposquat, code à l'installation, code obfusqué, secrets, domaines.
  3. 03SandboxSans réseau réel, avec de faux secrets uniques : le paquet se trahit s'il les lit.
  4. 04IA localeExplique en français et cite ses sources. N'aggrave qu'un doute réel.
  5. 05PolitiqueLe code décide : bloquée, à revoir par un humain, ou approuvée.
  6. 06SignatureEd25519. La passerelle refuse tout le reste.
  7. 07Après coupRévocation en un geste ; l'inventaire dit quels serveurs l'ont.

6 Compromission et si la plateforme est prise ?

Un attaquant root sur la plateforme peut

  • signer une version piégée avec la vraie clé ;
  • élargir la liste des API autorisées ;
  • réécrire sa propre base.

C'est le risque principal, et nous le disons. Prochaine étape : la clé de signature sur une clé matérielle, avec une double signature humaine.

Un attaquant root sur la plateforme ne peut pas, vérifié sur AWS

  • se connecter au serveur ni à la passerelle : SSH refusé avec chaque clé de la plateforme ;
  • donner Internet au serveur : aucune route, c'est le réseau qui le tient ;
  • publier avec une autre clé : 401 ;
  • effacer le registre des publications, gardé par la passerelle.

7 Principes ce qui ne se négocie pas

PrincipeConséquence
Les serveurs ne parlent jamais à InternetTout passe par la passerelle, qui n'a elle-même aucune route vers Internet.
Le code décide, l'IA alerte et expliqueL'IA ne peut ni approuver ni bloquer, ni créer seule un doute.
Rien n'est publié sans signatureLa passerelle refuse tout manifeste mal signé, ou dont un fichier diffère.
Tout localIA, sandbox et base de connaissances tournent chez vous. Seuls des noms de paquets publics sortent.
