**J'ai touché aux dossiers de C et de A** : c'est dit ici (règle 2), et tout est relisible dans

## Fait
### Côté B (`plateforme/pipeline/`, PR #97, fusionnée)
- **Registre npm** (`npm.py`) : versions stables et non dépréciées ; intégrité `sha512`
  vérifiée (`sha1` à défaut).
- **Versions et plages npm** (`semver.py`) : `^`, `~`, `x`, `a - b`, `||`. Une plage hors
  semver (`latest`, git, `file:`) est refusée.
- **`demander()`** : npm avec ses dépendances, chacune dans sa plage ; deux versions si deux
  plages sont incompatibles.
- **Veille** : une version dépréciée ou dépubliée pendant l'attente est bloquée ; OSV est
  interrogé avec l'écosystème `npm`.
- **Analyse statique npm** :
  - scripts `preinstall`/`install`/`postinstall`, fichiers qu'ils lancent, fichier principal ;
  - JavaScript : `child_process`, `eval` de base64, secrets plus réseau ;
  - typosquat sur les 5 000 paquets npm les plus téléchargés ;
  - éditeur de la version (`_npmUser`) changé.
- **Fausses alertes sur de vrais paquets :** 2 sur 212 paquets npm populaires (esbuild,
  @swc/core). Ils lancent des commandes à l'installation : ils passent « à revoir », comme avec
  pnpm 10, qui n'exécute aucun script d'installation sans approbation.

### Côté C (`plateforme/sandbox/`, `plateforme/signature/`, `passerelle/`, `infra/`)
- **Sandbox** :
  - même conteneur verrouillé, même piège, mêmes leurres ;
  - image `sas-sandbox-node:2` (`Dockerfile.node`, Node 20 sur Debian trixie, avec `strace`) ;
  - scénario `lancer_npm.sh` : le paquet est déposé dans `node_modules`, ses scripts
    d'installation sont lancés par `npm rebuild` sans réseau, puis il est importé. C'est
    l'équivalent de `pip --no-deps`.
  - npm lit sa propre configuration dans `~/.npmrc` : on lui en donne une vide hors du HOME,
    sinon chaque paquet aurait « lu le leurre ».
- **Signature** : npm passe **seulement** par la publication signée, pas par le stub `scp`.
- **Passerelle** :
  - une publication npm signée va dans **Verdaccio sans source amont** (`passerelle/verdaccio.py`),
    jamais dans pypiserver ; la révocation suit le même chemin ;
  - sans Verdaccio, la réponse est 503, avant toute vérification, donc le nonce reste libre ;
  - inventaire npm lu dans le journal de Verdaccio (`passerelle/inventaire_npm.py`) ;
  - la passerelle ne dépend toujours pas du code de la plateforme (un test le garantit).
- **Infra** :
  - `infra/aws/installer_npm.sh` (à lancer après `installer.sh`) : Node, dont la somme SHA-256
    est vérifiée, et Verdaccio passent par le poste de l'opérateur ; la clé de la plateforme
    n'est pas réutilisée (C3) ;
  - compte `recepteur` seul éditeur, inscriptions fermées ensuite ;
  - le serveur reçoit Node et un `npmrc` pointé sur la passerelle ;
  - `verdaccio.yaml`, `verdaccio.service`, `recepteur.service` (jeton et journal), `httpx`
    ajouté aux wheels du récepteur.

## Vérifié
- Suite complète : 715 verts, 6 sautés.
- Tests qui tournent avec un vrai Docker : sandbox npm (paquet piégé pris, paquet sage propre) et
  client contre un vrai Verdaccio (aucune source amont, rien ne s'écrit sans le jeton).
- **Essai de bout en bout en local :**
  - un registre amont, puis web et pipeline, vraie sandbox, signature, récepteur en TLS mutuel,
    Verdaccio de la passerelle, enfin un vrai `npm install` ;
  - `demo-npm-sain` est demandé, analysé, approuvé, signé, publié, puis installé avec
    `npm install` ; son `require` marche ;
  - `demo-npm-piege` est **bloqué** : exfiltration de `~/.npmrc` en statique ; en sandbox, le
    leurre `~/.npmrc` est lu, un DNS part vers l'attaquant et `sh -c node post.js` est lancé.
    Il est **introuvable** sur la passerelle (404) ;
  - la révocation depuis l'interface retire l'archive de Verdaccio ; l'inventaire et la fiche
    suivent ;
  - **un défaut trouvé et corrigé** : un fichier de jeton vide donnait une erreur 502 ; il vaut
    maintenant « pas de npm » (503).

## Limites
- **Pas vérifié sur AWS** : `installer_npm.sh` reste à lancer par C, ce que mon environnement ne
  peut pas faire.
- La sandbox n'installe pas les dépendances (comme pour pip) : chacune passe sa propre analyse.
- L'agent d'installation de la démo (`/v1/install`, panneau « Serveur ») reste pip seulement.
- La mesure (`mesure/resultats.md`) est sur PyPI. Il n'existe pas de corpus npm pour l'instant.
