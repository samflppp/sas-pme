# Point C (STEUSSO) — M1 : sandbox v1 — 2026-10-10

## Fait
- **`sandbox.executer` réel** (Docker). Chaque analyse a son réseau Docker **interne**, sans route
  vers Internet. Il contient deux conteneurs :
  - le **piège** : faux DNS qui répond à tout, faux serveurs TCP/HTTP qui notent tout. Son journal
    est hors de portée du paquet ;
  - la **cible** : lecture seule sauf `/tmp`, aucune capacité, sans root, 1 Go et 256 processus au
    plus.
- **Leurres uniques à chaque analyse** :
  - variables `AWS_SECRET_ACCESS_KEY`, `GITHUB_TOKEN`, `NPM_TOKEN` ;
  - fichiers `~/.aws/credentials`, `~/.ssh/id_rsa`, `~/.npmrc`, `~/.pypirc`, `~/.git-credentials`.

  Un leurre qui sort par le réseau est reconnu, même en base64 ou en hexadécimal.
- **Scénario** : installation sans réseau (le `setup.py` d'un sdist tourne sous surveillance), import
  (les `.pth` aussi ; si le nom d'import diffère, essai des modules trouvés), attente de
  `SAS_SANDBOX_ATTENTE` s (10 par défaut).
- **Essai réel** : un paquet sain donne un rapport vide. Un faux paquet piégé, qui lit
  `~/.aws/credentials` et l'envoie avec `GITHUB_TOKEN` à `collecte.attaquant-demo.example`, donne :
  `requetes_dns=['collecte.attaquant-demo.example']`, `connexions=['…:80']`,
  `fichiers_sensibles=['~/.aws/credentials']`,
  `leurres_lus=['~/.aws/credentials', 'GITHUB_TOKEN (exfiltré)', '~/.aws/credentials (exfiltré)']`.
- Si Docker est en panne, `executer` lève une erreur, et `traiter()` met la version `a_revoir`,
  jamais `approuvee`. `SAS_SANDBOX=stub` garde le rapport vide pour les tests.
- `installer.sh` installe Docker sur la plateforme. L'image `sas-sandbox:1` se construit à la
  première analyse.
- 18 nouveaux tests, dont 2 avec un vrai Docker (marqueur `docker`, sautés sans Docker). Chaque règle
  a été cassée une fois.
