# Point B (Mouabd19) — M1 : LLM local confiné — 2026-10-10

## Fait
- **`pipeline/llm.py`** (contrat § 6) : `POST {SAS_OLLAMA_URL}/api/chat`.
  - `format` est le schéma JSON de `VerdictLLM`, la température vaut 0, `stream` est désactivé.
  - Réglages : `SAS_MODELE` (`qwen2.5-coder:3b` par défaut, pour le CPU) et `SAS_OLLAMA_URL`
    (`http://127.0.0.1:11434` par défaut).
- **Entrées** : les constats (avec leurs extraits ≤ 200 caractères), le rapport de sandbox et les
  passages du RAG (vides jusqu'au M2). Chacun est entre `<donnee>`, et `<` / `>` sont échappés : un
  texte du paquet ne peut pas fermer la balise. Le prompt système dit que ce sont des données,
  jamais des instructions.
- **Sortie validée** :
  - des signaux `LLM` de niveau **au plus FORT** ;
  - une explication en français (≤ 800 caractères) ;
  - des références, seulement celles des passages fournis (une citation inventée est écartée).

  Aucun champ ne permet d'approuver. Un champ inconnu, un niveau `bloquant` ou un extrait trop
  long → réponse **ignorée et journalisée** (`llm_hors_schema`). Ollama injoignable →
  `llm_indisponible`, et l'analyse continue sans lui.
- **Dans `traiter()`** : le LLM reçoit les constats et le rapport. Ses signaux passent par la
  politique (un FORT met « à revoir »). L'explication va dans `Verdict.explication_llm` et les
  références dans `Verdict.refs_rag`. Testé : un LLM « rassurant » ne fait pas approuver une
  version bloquée.
- 283 tests passent. Le code a été cassé six fois pour voir les tests au rouge.
- Test avec un vrai Ollama : `pytest -m ollama`, sauté sans Ollama. Je n'ai pas d'Ollama ici,
  donc **pas encore vérifié avec le vrai modèle**.
